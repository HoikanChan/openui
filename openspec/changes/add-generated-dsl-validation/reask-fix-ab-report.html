给形式化验证专家的一句话

目前实现的是一个“流式语句安全门 + 有界一次修复器”：它能证明某些局部安全属性，却没有建立修复函数的终止性、完备性或全局不变量保持证明。

系统到底证明了什么

把确定性验证属性、经验性模型结果和当前不可判定范围分开，避免把“拦截成功”误写成“生成正确”。

真实错误原文 · t07 / t07-after

模型当前具体犯什么错

错误不是单一“语法错”，而是 JavaScript 惯性、契约错配、作用域混淆、结构复杂度和续写完整性五类机制叠加。下面每项都给出真实或等价保真原文、validator 观察、反思动作与终局限制。

01 · JS 数组方法与箭头函数

原始错误baseline.map(item => item.value)
validator 观察syntax-unclosed-bracket 与 syntax-unexpected-token；箭头中的 = 打断解析。
反思动作提示改为数组 pluck baseline.value，或 @Each(baseline, "item", item.value)。
终局 / 限制最高频、相对可修；但改对这一行仍可能因下游引用缺失而整篇失败。

02 · 严格等于与成员判断

原始错误row.key === "avg_roam_time" / arr.includes(x)
validator 观察=== 产生 Unexpected token EQUALS；成员方法属于 JS API 泄漏。
反思动作=== / !== 改为 == / !=；成员判断展开成 x == a || x == b。
终局 / 限制当前本地 builder 已加按需 rewrite，但尚无使用这版 prompt 的新 live A/B。

03 · JS 转换方法

原始错误data.totalDevices.toString() / v.toFixed(1)
validator 观察零参 toString() 会产生语法错误；单参数 toFixed(1) 是当前 parser 盲区。
反思动作"" + x 或 @FormatNumber(x, 1)。
终局 / 限制同一家族存在“可拦”和“漏拦”两种结果；没有 issue 就不会触发反思。

04 · JS 全局对象

原始错误Math.abs(data.delta)
validator 观察语法层可解析，引用层报 unresolved-ref "Math"。
反思动作提示使用 @Abs、@Round、@FormatNumber 等 builtin。
终局 / 限制依赖引用白名单兜底，不是语法系统自动区分 JS 与 DSL。

05 · 编造或过时组件

原始错误cardHeader(...) / VLayout / Text / @Div
validator 观察unknown-component；完整真实文件曾同时出现 32 个 unknown component。
反思动作给出最小相关签名，要求只使用 catalog 中注册组件，不发明 helper。
终局 / 限制候选替换通常不唯一；旧名迁移与真正幻觉在错误码上相同。

06 · @Render 参数与 binder 作用域

原始错误@Render("v", expr, 2)
validator 观察双 binder 形式要求第二参数是字符串；错位后常表现为 unresolved-ref "v"。
反思动作回放 @Render("v", expr) 与 @Render("v", "row", expr) 两个签名。
终局 / 限制三轮反馈仍可能不改，错误目录将其归入 prompt 收益递减的模型能力墙。

07 · @Each 中写 JS 块语句

原始错误@Each(items,"d",{ id = d.id ... })
validator 观察对象位置出现赋值语句，产生 syntax-unexpected-token EQUALS。
反思动作要求 template 是单个表达式：@Each(items, "d", {id: d.id})。
终局 / 限制Gate A/B 中 sparse-nullable 一次 reask 后仍无效，最终以 INVALID 扣留。

08 · excess args

原始错误Card(..., fourthArg)
validator 观察Card takes 3 arg(s), got 4。
反思动作给出精确组件签名，要求按 positional 参数重写整条语句。
终局 / 限制历史三轮反馈仍残留；同时 TS renderer 可能丢弃多余参数继续渲染，属于 validator 与 renderer 的产品语义决策点。

09 · 深层嵌套括号失衡

原始错误@Render、@Switch、三元与组件调用嵌套三层以上后少括号或多括号。
validator 观察syntax-unclosed-bracket 与 syntax-unexpected-token R_BRACE 成组出现。
反思动作要求重写整条语句并闭合 () [] {}，不要原位补 token。
终局 / 限制actual-target-gap 证明可修，但相同策略在其他复杂语句上并不稳定。

10 · 续写截断与未闭合引用

原始错误修复语句后提前停止，后续布局引用 roamCard、coverageCard、throughputCard，却从未定义。
validator 观察终局 unresolved-ref；无效的终端语句被扣留，因此落盘 DSL 看起来只剩局部前缀。
反思动作当前本地 prompt 新增 Completion contract，要求定义所有引用并以 root 收尾。
终局 / 限制这是“局部修复成功 / 全局完整性失败”的核心模式；新契约尚无 fresh live A/B 证明。

机制剖面

反思不是自由复写，而是受约束续写

系统先冻结已接受前缀，只把第一条无效完整语句、结构化 issues 和相关签名反馈给模型；模型只能从错误语句处继续写。

  1. LLM delta：持续接收模型输出。
  2. statement boundary：只在识别到完整赋值语句后触发校验。
  3. validator：语法、组件契约、引用与 root 检查；无效语句不公开。
  4. reask：拼装 accepted prefix + invalid statement + issues + signatures。
  5. same gate：修复续写再次经过同一个 gate。
  6. 终局：VALID，或达到错误 / done 条件后给出失败语义。

当前本地构造 · 非历史 live 请求

当前代码实际会加入的 Completion contract

## Completion contract (critical)
- The same mistake pattern may recur later in the document. Apply the SAME correction to EVERY later occurrence, not just the first.
- Your continuation MUST complete the document: every identifier referenced anywhere (in the accepted prefix or your continuation) must be defined by the end.
- `root` is NOT defined yet. Your continuation MUST end with a `root = Stack([...])` statement wiring the top-level layout.
- Do NOT stop after the corrected statement. Keep writing until the document is complete.

当无效语句包含 .map(... => ...) 时，当前本地 builder 还会实际加入：

## Rewrite these JavaScript patterns (openui-lang has no JS methods/operators)
- Array `arr.map(x => x.f)` → pluck `arr.f`, or `@Each(arr, "x", x.f)`.

证据限定：这些文本来自当前 worktree 的 ReaskPromptBuilder 构造结果，并由单元测试覆盖；它们不是下面 2026-07 历史运行的真实请求内容，因此不能拿历史效果反推这版 prompt 的效果。

反例与失败机理

为什么反思修复会失败

01 · 局部诊断，全局目标

issues 针对“第一条无效语句”，而完成条件涉及整篇引用图、root 可达性和后续所有语句。局部错误反馈并不包含全局修复证明。

02 · 修复预算只有一次

当前实验配置 maxAttempts=1。第二次输出仍无效时不会进入迭代收敛过程，而是直接结束为 INVALID。

03 · accepted prefix 不可回写

已接受前缀被冻结且明确禁止重发。这保护流式稳定性，却意味着前缀中已被语法层接受的语义坏选择不能被反思重构。

04 · validator 有观测盲区

数据 schema 不参与校验，单参数成员调用也会漏过。没有 issue 就不会触发 reask，修复器对这类错误完全不可达。

05 · prompt 是建议，不是证明义务

签名、错误码和 Completion contract 只能改变模型概率，无法强制它遵守“定义全部引用”或保证输出终止于合法 root。

06 · 错误到修复不是单值映射

unknown-component、binder 错位和深层括号错误往往有多种合法改写；validator 能证伪当前项，却不能构造唯一正确项。

07 · 上下文与续写长度压力

reask 同时携带原请求、accepted prefix、错误语句、issues、签名与规则。模型可能修好最近错误后提前结束，形成 continuation truncation。

08 · 视觉与业务语义在系统外

即使语法、契约、引用全部合法，也可能选错数据、漏字段、布局失衡或格式不佳；这些不会由当前 reask 机制自动变好。

三个当前真实 known miss

root = Table([Col("Name", "name")], data.data.users)
root = Table([Col("Name", "nmae")], data.userz)
root = TextContent(data.value.toFixed(1))

当前 corpus 将它们标为 expectedOutcome: missed，三者均返回 no validator issues。前两项需要 dataModel schema 对照；第三项需要收紧上游语言语法或在 eval / runtime 层补充规则。

实验限制必须和结果一起阅读

  • Gate A/B 的 44 个 fixture 中有 5 个顶层数组因 Java SDK Map 数据模型限制被跳过。
  • OFF / ON 两臂是独立模型采样；即使 temperature=0，服务端输出仍可能波动。
  • Judge 的相同 DSL 对照也出现 ±1 漂移，报告将 |Δ|≤1 视为噪声。
  • 文档引用的两个 eval run 目录与截图当前不在 worktree，不能现场复核视觉判分。
  • 当前 Completion contract 与新增定向 rewrite 只有本地构造和单测证据，没有 fresh live A/B。
