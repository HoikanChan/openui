状态口径。只有会话以 CHECK_PASSED 结束、最终校验为 VALID，且输出 DSL 与最后一次通过校验的 DSL 完全一致时，才计为「已修复」。其余一律以红色标记为「未修复」：still-invalid 尝试耗尽并输出 Markdown 降级占位；not-reproduced 的原始 DSL 本身通过校验（未执行修复），不计入主修复率。
Diff 口径。BEFORE 为 repair-cases/<案例目录>/dsl.txt 中的原始 DSL（按 case.json 的 id 匹配）；AFTER 对已修复案例为 JSONL outputDsl， 对未修复案例为最后一次校验的 DSL（finalDsl）。Markdown 降级占位不展示，也不参与 diff。
反思 Prompt。运行产物未保存 Prompt 原文；报告按 SDK RepairPromptBuilder 的模板，从每轮已存字段还原用户消息（原始需求、当前有效 DSL、 本轮原始输出、最新诊断、历史轮摘要）。系统消息中的完整契约、原始 system prompt 与固定增量规则未展开； 「相关语句」按文本引用近似还原，专项指导按 RepairGuidance 规则还原。
每轮详情。多轮案例默认只展开最后一轮；其余轮次点击展开。每轮的 「累积 DSL」可单独展开，内容是该轮 currentDefinitions，并高亮诊断语句与诊断行。 「问题语句」取该轮 DSL 中诊断 statementId 对应的完整语句；无 id 时按诊断行号归属。 反思 Prompt 是下一轮的用户消息：第 0 轮的 Prompt 用于第 1 轮修复；最后一轮若已通过校验则不再生成， 若未通过则因尝试次数/预算耗尽而未发送。
本报告由 repair-bench 每次运行后自动生成。源文件： · 模型 · 生成时间 。 初始问题码来自原始 DSL 的校验；内部问题码是案例 issues.json 的元数据，不是校验结果。 页面不使用任何网络资源。
